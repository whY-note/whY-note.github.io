# Tourism 地点维护

将用户提供的到访地点维护到本站旅行地图，沿用下列已经确认的命名、语言和布局要求。文中所有项目路径均相对于仓库根目录。

## 修改范围与页面约定

- 页面地址为 `/life/tourism/`，Life Room 的 World Map 和“世界地图”菜单都指向这里。
- 浏览器标签的页面标题为 `Tourism`，保留公共 SEO 模板附加的站点名称；页面内主标题为 `Places I Have Been`。
- Tourism 自有的标题、统计、按钮、操作提示、加载失败提示和无障碍标签使用英文；中国地点的三处中文显示是下述明确例外。
- 保留原有 Header、页脚、作者中英文姓名、页脚引语和主题切换文案。普通地点维护不要改 `_includes/header.html`、`_includes/footer.html`、`_includes/seo.html`、`assets/js/main.js` 或其他站点公共文件；不要为了让 Tourism 全英文而改这些内容。
- 不重新添加已经删除的导语“把走过的路，收藏在地图里。选择一个标记或城市，重访旅途中的坐标。”或其英文译文。
- 沿用星空／白色主题、地图与城市清单联动和现有手机布局。地点维护默认只修改本地仓库；提交、推送、发布以用户的明确要求为准。

## 地点数据与命名

唯一地点数据源为 `_data/travel_places.yml`。新增地点通常只需追加数据；不要在模板或脚本内另建地点列表、写死统计数量。

| 字段 | 填写规则 |
| --- | --- |
| `name` | 英文地点名，例如 `Shunde`、`Daocheng Yading`、`Sydney`、`Perth`。使用正常英文大小写，保留名称中的空格。 |
| `name_zh` | 中国地点必须填写准确的中文名，例如 `顺德`、`稻城亚丁`。非中国地点不要求填写，展示时也不自动加中文。 |
| `country` | 英文国家名，例如 `China`、`Australia`。 |
| `country_code` | 一致的 ISO 两位大写国家代码，例如 `CN`、`AU`。本项目已将香港归入 `China` / `CN`，沿用该数据约定。 |
| `coordinates` | 两个数字，顺序固定为 `[纬度, 经度]`，使用与 Leaflet / OpenStreetMap 一致的经纬度坐标。纬度范围 −90 至 90，经度范围 −180 至 180。 |
| `zoom` | 可选，点击地点后的缩放级别；默认 `8`。较大地区可用 `5` 或 `6`，景区可用 `10`，按地点范围选择。 |

示例仅说明格式，不代表可以额外添加用户没有提及的足迹：

```yaml
- name: Shunde
  name_zh: 顺德
  country: China
  country_code: CN
  coordinates: [22.8000, 113.3000]

- name: Daocheng Yading
  name_zh: 稻城亚丁
  country: China
  country_code: CN
  coordinates: [28.3700, 100.2200]
  zoom: 10

- name: Sydney
  country: Australia
  country_code: AU
  coordinates: [-33.8688, 151.2093]
```

- 保留既有地点及顺序，按用户给出的顺序追加新地点；先检查中英文别名是否对应已有条目，避免重复添加。
- 只记录用户提供的真实足迹，不加入参考网站作者的城市或演示地点。
- 地点可以是城市、地区或景区。用户只说“山东”“西藏”时，保留地区记录，用地区代表点并在数据注释说明，不推断其到访了济南、拉萨等具体城市。稻城亚丁应标在景区，不能替换成稻城县城。
- 用户没有提供坐标时，查证同名地点、行政归属和适当的代表点；有歧义时结合上下文辨认，必要时询问。地区、景区等代表坐标可在数据注释保留来源，不虚构游览路线或日期。
- 所有条目参与地点数量统计，国家数按 `country_code` 去重。标签使用 `Places` / `Countries`，数量为一时使用单数；不要把地区和景区全部称作 `Cities`。

## 中国地点的三处中文显示

以 `country_code == "CN"` 判断，复用 `name_zh`，不要通过英文名称猜测是否属于中国。

| 位置 | 中国地点 | 其他国家的地点 |
| --- | --- | --- |
| 地图标记的浮层与原生标题 | `西藏，中国`，即中文地点名、中文逗号、`中国`。 | `Sydney, Australia`，沿用英文地点和国家名。 |
| 地图旁的 Selected place 详情区 | 中文名在英文名**上方**独占一行，例如先显示 `顺德`，再显示 `Shunde`；中文与英文字号、字重相等，桌面和手机端都一致。下方国家名仍为英文 `China`。 | 仅显示英文名与英文国家名；切换过去时清空并隐藏上一地点的中文名。 |
| Visited places 地点卡片 | 中文名在英文名**左侧**，例如 `顺德 Shunde`、`稻城亚丁 Daocheng Yading`；两种语言字号、字重一致，下方国家名仍为 `China`。同步维护按钮的无障碍名称。 | 仅显示英文名和英文国家名，不额外加中文。 |

地图浮层与详情、卡片有不同格式，不要直接把 `name` 改成中文或拼接好的双语字符串。底图自带地名由瓦片提供方决定；更改浮层不代表需要替换底图或地图库。

## 地点卡片的尺寸与长名称

- 在同一视口下，每个地点框的宽度和高度都相同，包括跨行的卡片；选中、悬停或长地名不能撑大某张卡片或某一行。
- 每张卡片的中文名与英文名必须完整放在**同一行**。不要换行、拆词、用省略号隐藏或裁掉名称，也不要只为长名称加宽卡片。
- **只缩小放不下的那张卡片中的中英文地名。** 两种语言作为一组同步缩小，其他能正常放下的地点保持原字号。不要取全列表最小字号统一应用，也不要降低所有卡片的字号来迁就稻城亚丁。
- 仅调整名称行；国家名、右侧详情区及其他卡片不随之缩小。
- 卡片变宽后，先恢复名称的正常字号，再独立判断是否需要缩小；字体加载完成、窗口或卡片宽度改变后重新测量。
- 延用 `life/tourism/cards.js` 的逐卡片自适应逻辑，中文 span 从同一个名称容器继承字号。保留等高网格及响应式列数；窄屏可减少列数，避免文字缩得过小。
- 卡片右侧使用向右的尖括号 SVG（chevron），不要恢复成 `+`。所有卡片的图标尺寸和对齐方式一致。

## 实现位置与检查

先读取当前实现，再作最小必要修改；普通追加地点优先保持现有模板和交互逻辑。

- `_data/travel_places.yml`：地点数据和代表坐标说明。
- `life/tourism/index.html`：统计、详情区、卡片双语文本、无障碍标签及脚本引用。
- `life/tourism/script.js`：地图标记、中文浮层、详情联动及可选缩放级别。
- `life/tourism/style.css`：两种主题、详情字号、等大卡片、单行名称和响应式网格。
- `life/tourism/cards.js`：逐张测量和缩小名称，不能改成全列表统一缩小。
- `docs/life.md`：项目维护说明；字段或行为变化时同步更新，避免重复维护固定地点总数。

在仓库根目录执行适合本次修改的检查：

```bash
jekyll build
# 修改对应脚本时，再执行：
node --check life/tourism/script.js
node --check life/tourism/cards.js
git diff --check
```

Node 未加入 PATH 时可使用本机已安装的 Node 可执行文件；站点本身无需 npm 或新增打包工具。不必为普通地点追加重新生成房间模型。

核对新增地点的数量、国家去重、坐标顺序、三处名称和地图／卡片点击联动；未改动的地点保持原顺序。涉及布局时，在浏览器可用的条件下检查桌面及窄屏、星空及白色主题：稻城亚丁完整单行、其他短名保留正常字号、全部卡片等大，切换地点不会残留中文。浏览器不可用时如实说明验证范围，不把构建通过描述成视觉验证通过。
